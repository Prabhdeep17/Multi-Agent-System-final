📋 The PolicyState Dictionary

LangGraph orchestrates independent agent functions. They share state through a TypedDict that is passed node-to-node. Two new fields were added in v2.0 for the Data Critic loop.

query
The user's raw question text
intent
Determined by Router: "data_analysis", "document_search", "general"
chat_history
Last N turns for conversational context
generated_code
Pandas code written by Data Analyst agent
data_analysis_result
Raw Python output — the ground truth for the Critic
math_critic_feedback
Code errors caught by Math Critic to trigger a re-run
final_answer
The Writer's formatted narrative draft
retrieved_chunks
PDF blocks fetched from FAISS by Retrieval Agent
data_critic_feedback NEW
"PASS", "PASS_LIMIT_REACHED", or the specific hallucinated stat found
data_critic_loop_count NEW
Tracks how many times the Critic loop has fired. Hard limit: 2.
1 Memory

💾 vector_store.py

Handles file ingestion. Uses LangChain loaders for PDFs and Pandas for CSVs/Excel. Serves FAISS-based semantic search for the RAG pipeline.

⚠️ Tabular Bypass Logic
In load_and_chunk_docs(), CSV and Excel files are explicitly skipped from FAISS ingestion. FAISS is terrible at doing arithmetic on rows. Instead, the Data Analyst agent reads the raw CSV directly via Pandas at runtime.

Dirty Data Resilience

When loading CSVs, the system uses encoding_errors='replace' and df.fillna(""). This prevents crashes on corrupted or poorly-formatted spreadsheets uploaded by end users.

Performance Caching (@st.cache_data)

CSVs are cached in memory using Streamlit's @st.cache_data decorator via a load_dataframe_cached() wrapper. The cache key includes the file's os.path.getmtime() timestamp, so the cache automatically invalidates if the source CSV is updated on disk — preventing stale data responses.

2 The Brain

🤖 The Smart Router (Universal Context Injection)

The most intelligent part of the system. Completely removed hardcoded intents. The Router dynamically inspects every file in the session folder before making a routing decision.

How Context Injection Works

Before the Router LLM even sees the user's query, a Python pre-processing script peeks inside every uploaded file:

  • For CSV/Excel: Extracts the column headers and first 2 rows of data.
  • For PDFs: Records the filename and type.

This raw preview is injected into the System Prompt. So even if a user uploads a file named Untitled_Data_1.xlsx, the Router sees the actual column names like [lead_qualification, current_stage_stage, createdAt] and routes correctly to the data pipeline.

3 Pipeline A · Step 1

📊 The Data Analyst (Code Execution)

When the Router outputs intent: data_analysis, the graph routes here. This agent generates raw Python/Pandas code to answer the user's query.

Hardened exec() Sandbox (v2.1)

Running LLM-generated code is dangerous. Code runs inside a restricted dictionary that exposes only Pandas and safe built-ins. Recent updates hardened this sandbox:

exec_globals = {
    "pd": pd,
    "np": np,
    "re": re,
    "__builtins__": {
        "vars": vars, "globals": globals, "locals": locals,
        "enumerate": enumerate, "zip": zip, "type": type,
        "isinstance": isinstance, "round": round, "KeyError": KeyError
    }  # Disables import, open(), os.system()
}

Fix 1: Variable Scope. The uploaded dataframes are now mapped directly into exec_globals rather than locals(). This allows the AI to write complex list comprehensions and isolated helper functions without crashing due to NameError scope issues.

Fix 2: RegEx Sanitization. All uploaded file names are forced through re.sub(r'\W+', '_', ...) to remove spaces and hyphens. A file named sales-data.csv is cleanly mapped to the python variable sales_data to prevent fatal SyntaxErrors.

Fix 3: Bulletproof Code Extraction. To completely prevent "unterminated string literal" parsing bugs caused by nested backticks, the system now uses backward string searching (content.rfind("```")) instead of fragile regular expressions to extract the python block. Additionally, the prompt strictly forbids the backtick character anywhere in the AI's Python code.

📝

Data Writer Agent (v2.2 Strict Mode)

Takes the raw Python execution result and formats it for the user.

Strict Output Rules

  • Strict Relevance: Answers ONLY the explicit question asked. Unsolicited explanations, tutorials, and business strategy are completely banned to prevent verbose responses.
  • Conditional File Naming: If multiple files are uploaded, it explicitly cites which datasets were analyzed. If only a single file is present, it omits the redundant file name mention.
  • Zero Hallucination Contract: Must rely exclusively on the mathematical output from the Sandbox. If data is missing or 0, it must state exactly that.
4 Pipeline A · Step 2

🛡️ The Math Critic (Code Self-Healing Loop)

LLMs are notoriously bad at writing correct Pandas code. The Math Critic sits directly after the Data Analyst to catch code execution errors before they reach the user.

🔄 The Code-Level Self-Healing Loop
If the exec() threw a Python exception (e.g., KeyError: 'wrong_column' or a TypeError), the Math Critic writes that error into math_critic_feedback and the graph loops back to the Data Analyst. The Analyst reads the error, corrects the code, and tries again. This prevents silent failures from reaching the user.
5 Pipeline A · Step 3

✍️ The Data Writer (Adaptive Senior Analyst)

Once the Math Critic approves the raw Python output, the Data Writer formats it into a professional, readable narrative.

Adaptive Formatting Rules

The Writer's system prompt contains five explicit rules that prevent it from acting like a robotic report generator:

  • ADAPT TO THE QUERY: Simple questions get short answers. Complex analysis gets structured breakdowns. No fixed templates.
  • ORGANIC INSIGHTS: Business context is woven naturally into the narrative, never forced into a hardcoded "Analyst Insight:" header.
  • NO BOILERPLATE: Never outputs "Status: Active", file paths, or system notes.
  • ZERO HALLUCINATION CONTRACT: If a result is 0, report exactly 0. Never fabricate statistics to satisfy a strategy request.
⚠️ The Hallucination Problem We Solved
When the Writer is asked for a "business strategy" but the data contains zero closed-won deals, it previously invented conversion rate statistics (e.g., "8.82% conversion rate") to make its answer sound credible. This is the exact problem the Data Critic was built to eliminate.
NEW Pipeline A · Step 4

🔬 The Data Critic (Hallucination Prevention Loop)

The newest and most critical agent in the system. This is the industry-standard Actor/Critic (Reflexion) Pattern applied to prevent the Data Writer from fabricating statistics.

How the Critic Works

The Critic receives two inputs simultaneously:

  1. The raw Python output from the Data Analyst — the mathematical ground truth.
  2. The Writer's draft narrative — the formatted response about to be sent to the user.

It extracts every single number, percentage, and statistic from the Writer's draft and cross-references them against the raw Python output. If any number in the draft does not appear in or is not directly deducible from the raw output, the draft is rejected.

The Loop Logic

def route_after_data_critic(state: PolicyState):
    feedback = state.get("data_critic_feedback", "PASS")
    if feedback in ["PASS", "PASS_LIMIT_REACHED"]:
        return END              # ✅ Output is verified
    else:
        return "data_writer"   # ♻️ Loop — rewrite with feedback

If rejected, the Critic's specific feedback (e.g., "You hallucinated the 8.82% conversion rate. Remove it.") is injected directly into the Writer's next prompt, forcing a factual rewrite.

🔒 Infinite Loop Guard
The Critic tracks how many times the loop has fired via data_critic_loop_count. If it reaches 2, the state is set to PASS_LIMIT_REACHED and the graph exits, preventing infinite loops. In this case, the best available draft (with caveats) is returned to the user.
6 Pipeline B

🔎 The PDF RAG Pipeline

If the query requires text knowledge from uploaded PDFs, it goes through 4 specialized agents in a linear chain.

  • Retrieval Agent: Executes vector similarity searches against FAISS. Deduplicates results. Scales top-k based on query urgency (12 for normal, 20 for high urgency).
  • Analysis Agent: Acts as a paralegal. Reads all retrieved chunks and extracts key rules, numbers, conditions, and exceptions into a structured format for the Writer to consume.
  • Writer Agent: Drafts a clean, professional markdown response using the extracted rules. Uses citation markers like [1], [2] to reference source documents.
  • Reviewer Agent: Compares the Writer's draft against the original FAISS chunks. If the Writer invented a policy that doesn't exist in the chunks, the Reviewer flags it and corrects the final output.

8 Frontend

🖥️ app.py (The UI)

The Streamlit application maintains completely isolated session folders so multiple conversations and datasets never bleed into each other.

Session Persistence Across Refresh

Sessions are stored on disk under session_docs/<session_id>/ and session_faiss/<session_id>/. On startup, the app reads sessions.json to restore the session list and reloads the FAISS index and CSV data from disk. This means refreshing the browser does not destroy your conversation history or uploaded files.

Live Streaming Agent Status

Because the graph can take 10-30 seconds (especially if the Critic loop triggers a rewrite), we use yield in the backend to stream real-time status updates to Streamlit's st.status() widget. The user sees exactly which agent is currently working — Router, Data Analyst, Data Critic — preventing the UI from feeling frozen.

Glassmorphism Active Files Banner

Custom CSS pins a dynamically-updating "Active Files" banner to the top of the viewport. It uses backdrop-filter: blur(16px) with an rgba background to create a frosted glass effect that persists during scrolling. It expands on hover via a CSS max-width transition to reveal full file lists without wrapping issues.
